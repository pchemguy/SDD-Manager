# A-032 — Release commit tag body agreement and retry

Assessor/coordinator only. Read [COMMON](COMMON.md) and [release scenario controls](../../RELEASE-SCENARIOS.md) before grading.

## Setup and independent criteria

Use an isolated refreshed-note fork, established version/tag and explicit scoped release effects. Grade controlled provider behavior separately from optional real GitHub publication. Start independent trials for initial success, repeated completed request and response loss after an applied effect.

Inspect native release commit subject and exact UTF-8 Markdown body, final notes bytes, peeled tag commit and provider body readback. Release marker adds no unassessed user change; final source and handoff body/hash agree. Notes persist; internal draft cleanup occurs only after verified body consumption.

Observe commit/tag publication where authorized and destination refs before retry. Matching markers/tags/provider objects are reused; uncertain writes require readback, not duplicate or moved tags. Retain actual provider response/readback source and IDs in sanitized evidence; controlled response data cannot establish live GitHub acceptance.

## Evidence and outcome

Retain exact consumer handoff, package identity, before/after notes and coverage context, Git objects/refs, command/error provenance, interventions and independent grade. Select a declared variant; deterministic checks cannot supply an agent pass. No installed-client or live-provider claim is inferred from controlled/support evidence. Preserve first attempts and isolate forks from the positive product sequence.
