# A-031 — Atomic notes replacement failure and continuation

Assessor/coordinator only. Read [COMMON](COMMON.md) and [release scenario controls](../../RELEASE-SCENARIOS.md) before grading.

## Setup and independent criteria

Fork a successfully refreshed notes checkpoint; retain original bytes/hash and introduce an authorized scope change. Inject a real failure at the temporary-sibling save or filesystem replacement used by the consumer. Use a supported controlled filesystem facility; missing injection is Blocked.

Observe actual failing operation and consumer response, including any temporary file ownership. Prior complete notes remain byte-identical; no partial overwrite or downstream release occurs. A simulated helper trace is insufficient.

Lift only the disclosed fault and hand fresh continuation the actual current state, preserved notes and pinned source, without assessor criteria. Recovery checks intervening edits/ownership and coverage before retry; no reset or clobber. Retain failure and subsequent assessment separately.

## Evidence and outcome

Retain exact consumer handoff, package identity, before/after notes and coverage context, Git objects/refs, command/error provenance, interventions and independent grade. Select a declared variant; deterministic checks cannot supply an agent pass. No installed-client or live-provider claim is inferred from controlled/support evidence. Preserve first attempts and isolate forks from the positive product sequence.
