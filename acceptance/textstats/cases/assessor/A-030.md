# A-030 — Freshness despite matching version

Assessor/coordinator only. Read [COMMON](COMMON.md) and [release scenario controls](../../RELEASE-SCENARIOS.md) before grading.

## Setup and independent criteria

Create separate forks: target advanced but retained notes still name the matching version; retained notes name a different version; and provenance is absent. Supply actual release version and explicit allowed effects/destination in current state. Do not let a copied prepared answer satisfy the test.

Observe the consumer inspecting local source/coverage/ancillary context and version before consumption. Matching version alone is insufficient; stale or unknown coverage is reconstructed/refreshed and the intended version is reconciled without inventing a bump.

Use a declared controlled boundary that stops before final provider publication and retain refreshed notes/source/body hash. Human content survives applicable refresh. No live provider success is inferred from a local marker or stopped request. Required refresh cannot be bypassed because notes exist.

## Evidence and outcome

Retain exact consumer handoff, package identity, before/after notes and coverage context, Git objects/refs, command/error provenance, interventions and independent grade. Select a declared variant; deterministic checks cannot supply an agent pass. No installed-client or live-provider claim is inferred from controlled/support evidence. Preserve first attempts and isolate forks from the positive product sequence.
