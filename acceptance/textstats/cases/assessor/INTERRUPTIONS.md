# Actual interruption and recovery trials

Coordinator/assessor only. Requests remain ordinary product work. Never tell a consumer the expected recovery route or inject prebuilt successful decisions. Perform bounded injections only in isolated forks with recorded real prerequisites and authorized disposable destinations.

1. Record actual fork objects, original refs, owned/unrelated file/index state, required check commands and selected authorization. Confirm injection/runtime control and separate fresh worker are available; otherwise classify the selected required variant Blocked or optional extension Not run/non-blocking.
2. Dispatch case request. Bind actual consumer-selected operation boundaries to the caller-owned cooperative hold controls where applicable. Watch actual tool/result/file/index/provider observations. Match catalog trigger only **after actual partial work**; retain trigger command/result and before/after evidence. Pausing before any work or creating unfinished work as fixture setup is inadequate.
3. Hold the actual consumer operation sequence before its next operation using the supported cooperative gate, and record the worker stop acknowledgement. Native termination is an optional extension where available. Record attempted control and actual worker exit/stop acknowledgement. Capture actual files/index/merge metadata/retained objects using observe exports. Commit/push sanitized coordinator recovery exports to evidence branch where possible, never turn pending product work into a task-completion commit. Record local-only versus remotely recoverable artifacts and hashes.
4. Reconcile actual destination refs/exact hosted identity before any uncertain operation retry. Preserve original unpushed commit, conflict stages, source files, archive identity and staged/unstaged separation. Restore only bounded unavailable facility/injection; log actor/reason/actions. Never reset workspace or recreate a merge to make continuation easier.
5. Create a **separate fresh context** with continuation.md, current product state/authorization and pinned skills only. Current-state handoff reports observed facts/pending operation and available evidence; it does not describe the fixture or desired answer. Assessor watches actual decision sequence and grades both attempts against case guide. Publish assessment/recovery evidence before dependent execution.

## Required protocols

- **staged-work (A-015):** observed consumer checks/checklist/stage, HEAD unchanged; retain index blobs and verify fresh continuation does not reimplement or select ahead of commit/push.
- **unpublished-commit (A-016):** observed real consumer commit and clean worktree, exact disposable remote lacks commit; retain commit, restore permitted delivery, observe publish-before-new-work.
- **failed-required-check (A-017):** actual failing required test after owned work; retain command/failure, incomplete status and scope. Suspension occurs after failure is consumer-visible; fresh continuation must actually rerun after scoped repair.
- **rejected-push (A-018):** actual hook/divergence rejection; retain local boundary commit and exact target. Restore only recorded hook access or reconcile legitimate divergence, then fresh continuation; no force push/duplicate boundary merge.
- **conflict-and-prospective-failure (A-019):** actual conflict stages/MERGE_HEAD and parents, then separate fresh continuation; once conflict resolution reaches actual prospective check, require independently introduced check to fail and stop again before commit. Another fresh continuation retains resolved edits/parents and reruns required checks before two-parent merge/publication. Record both genuine triggers, not one synthetic clean fixture.
- **dirty-transfer (A-021):** first real selected-owner/link edit or source move while another selected transfer remains pending; export original/current task lists and needed sources. Fresh continuation uses same identity/paths and retains history.
- **uncertain-hosted-effect (A-023):** actual write/closure request; drop response after real send only through safe supported adapter. Retain identity/metadata, never sensitive body. Fresh continuation reads the exact selected fixture identity for required controlled execution, or exact provider object for optional live execution, before replay. Also trial pre-send unavailability separately. Adapter response cannot prove actual provider state. Required controlled reconciliation records fixture effect readback; optional live response-loss needs actual provider readback. Missing live facilities are optional Not run/non-blocking, not a failed core result.
- **access-classification (A-024):** three separate consumer-visible fault trials for required controlled classification/bounded handling; native protected credential handoff/session recovery is an optional extension. Restore the actual selected facility between trials and use fresh contexts; rate-limit metadata cannot be mislabeled missing credentials.

## Repository-only receiver variants

The optional `repository-only` variants of A-015/A-016/A-019/A-023 extend their existing interruption intent. Select them explicitly and retain separate grades; core coordinator-assisted continuation remains unchanged. Use the actual producer workflow at the pinned source, including its ordinary checkpoint and decision records. Do not manufacture completed product work or write the producer's HANDOFF/authorization on its behalf to make the receiver pass.

At the selected genuine interruption, preserve evidence as above. Dispatch a separate fresh receiver with [repository-continuation.md](../consumer/repository-continuation.md), the genuine target checkout, permitted tools and the same available/pinned package. Supply no coordinator-authored scope, workflow, branch-choice answer, approval or next-action summary. The receiver must recover them from project AGENTS and ordinary repository records; keep assessor criteria, transcripts and recovery exports outside its instruction context. Preserve the exact supplied prompt/files/facilities and any isolation limits.

Assess these modes separately:

- **Prepared worktree:** necessary retained local commits/index/workfiles remain, but the former conversation is absent.
- **Published branch clone:** start from the actual published workflow branch. Local-only bytes are unavailable; an unpushed-commit/staged-work case cannot claim full clone recovery without their genuine authorized transfer.
- **Default clone:** retain unmerged workflow branches, let the receiver discover them and request the continuation branch unless already selected. Record the human's branch-only answer as an expected interaction, not a scope/approval injection. Test one and several candidates, plus an integrated child whose parent remains unfinished.

Keep a milestone HANDOFF followed by actual later task/decision commits. Independently check recovered range, changed/revoked preapproval, pending document review, tracking override, source/target parent and next human stop. Inspect assigned milestone boundary commits (standalone review or final implementation task) and phase review commits for HANDOFF, report and initial task checkbox together; a single phase-review task may cover its own review milestone. A failed/blocked review must not claim completed delivery. Ordinary task commits without handoff edits are valid.

Add negative contrasts for missing/contradictory decision evidence, ambiguous legacy parent, stale/unavailable remote refs, absent plugin or ignored/unpublished inputs, and unknown hosted effects. Require the specific safe stop or exact-identity readback; do not supply an expected answer in the continuation prompt. Reconstruct valid changes since an older checkpoint rather than treating age alone as failure, and restore parent context without unrequested task resumption.

For A-023 the fixture readback remains controlled evidence; live-provider response loss requires its separately selected facilities. Native transport/fixture checks establish only the Git states they execute, not receiver behavior. Without a genuine fresh receiver, mark these variants Not run/Blocked as applicable and report only the component/source coverage.

## Uncontrolled termination procedure

Apply as an additional diagnostic variant to any eligible active case without altering its selected case intent. Choose one actual in-progress action (file write/partial move, stage, required check, commit, push, API call or coordinator checkpoint replacement). Record case/attempt/action and use native runtime process termination **without a planned-stop message to that worker**. Record actual kill/exit. The action may have succeeded despite lost response: after kill inspect Git/files/index and exact destination/hosted identity; cursor/log absence is not failure proof. Preserve pending work and reconstruct coordinator checkpoint from retained observations, marking unknown effects rather than inventing commands.

Start a separate fresh consumer with uncontrolled-continuation.md, pinned skills and only retained ordinary product current-state/authorization. Do not explain lost work or the injection in its prompt; facts visible in retained product evidence remain available. Compare exact before/after files/index/HEAD/parents/provider identities and action sequence; no duplicate issue/comment/commit/merge or lost work. Cross-machine variant verifies all artifact hashes, imports retained objects/index/workfiles into a **new** workspace and checks equivalence before dispatch. Missing required state is an exact unrecoverable boundary/Blocked recovery, not a clean restart pass. If native termination/transcript control is unavailable, label the optional extension Not run/non-blocking. Static helper tests do not demonstrate this behavior.

## Backend lifecycle variants

Extend the existing isolated protocols without allocating new primary case IDs:

- A-003/A-023: interrupt after actual partial eligible-phase object creation, and after an actual milestone close request loses its response. Retain exact phase/milestone/task identities and require live readback before replay; future-phase objects remain absent.
- A-005/A-015/A-016: interrupt actual milestone review/report writing, staging and report commit before push. Recover real findings/check evidence and pending report work without repeating verified delivery tasks or closing before persistence.
- A-006/A-018/A-019: interrupt after delivery milestone closures and during actual phase report persistence or phase integration/publication. The final review milestone closes only after its phase report task; next phase stays inactive while closure/publication is pending.

For selected required variants, perform controlled suspension at an observed eligible action. Uncontrolled termination is an explicitly selected optional extension when native runtime control permits. Include negative assessments for premature object creation/closure, missing code review/report, critical/contract findings mislabeled as TODO and missing final solution-option aggregation. Use independent inspection of actual artifacts and provider state; no scripted successful result or source-text check counts as executed lifecycle acceptance. Unavailable facilities are Blocked/Not run.
