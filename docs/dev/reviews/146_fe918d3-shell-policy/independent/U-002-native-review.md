### R-001 — Completion rejects multiline descriptions emitted by projection

**Severity:** medium (P2); **confidence:** high. **Location:** `.agents/plugins/sdd-manager/skills/sdd-forge/scripts/forge-close.mjs:32`.

**Trigger and evidence:** Use an otherwise eligible implementation milestone whose projected description is Outcome: bounded work. followed by LF and Exit: verified checks. validateProjection(..., true) and renderProjection accept/preserve the two-line description; actual forge-close.mjs task CLI --reconcile-only on an isolated real Git root exits 1 with invalid_milestone/preflight and no stderr.

**Consequence:** A legitimate projected implementation milestone blocks both task completion and milestone completion before provider access. The same validator also rejects multiline predecessor descriptions. Rewriting the hosted description to work around this would violate exact identity/content handoff.

**Bounded correction:** Allow the documented bounded multiline milestone-description text in milestoneInput (for example text(value.description, 16000, true)); keep null, control, reserved-marker and length checks and exact hosted comparison. Decide and document CRLF normalization consistently if added, rather than silently changing exact-content semantics.

**Objective recheck:** Add a cross-utility case that renders a valid phase request with an LF milestone description and hands that exact description into native completion run(), asserting a completed task and milestone with matching readback. Add a multiline predecessor case and retain invalid controls/marker/oversize negative cases. Run completion plus dependent projection suites and relevant native matrix.

**Severity:** low (P3); **confidence:** high. **Location:** `.agents/plugins/sdd-manager/skills/sdd-forge/scripts/forge-close.mjs:310`.

**Trigger and evidence:** Supply branch @{-1} in an otherwise valid completion handoff for a real repository with a previous checkout. Native git check-ref-format --branch @{-1} exits 0 and prints initial; native git check-ref-format refs/heads/@{-1} exits 1. The real public/native run() path with an isolated repository, actual ignored synthetic token and actual lock, injecting only HTTP, returns closed_verified/ok=true, posts Branch: @{-1}, and closes the issue as completed.

**Consequence:** The promised actual valid branch association is replaced with a context-dependent checkout expression in durable evidence. This does not redirect the API repository/issue or establish a forged commit; it weakens evidence accuracy and portability.

**Bounded correction:** Reject previous-checkout syntax and validate a literal branch identity. For example reject the forbidden @{ sequence in taskInput and/or require the native --branch validation output to equal the supplied branch; preserve the existing leading-dash/invalid-name checks and never evaluate then silently rewrite a caller assertion.

**Objective recheck:** Use a temporary real Git repository with two checkouts and assert public/native run() rejects @{-1} before token/network/lock writes as appropriate, with zero HTTP calls. Exercise another shorthand such as @{-2}, an invalid literal ref, and ordinary slash/Unicode branch names; rerun completion and relevant native matrix.
