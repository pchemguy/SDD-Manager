# Release message source assessment

## Evidence scope

This is a source walkthrough of the actual edited instructions, not fresh-agent consumer acceptance or live provider publication. The new forge reference owns complete-message lifecycle, report owns editorial assembly, and manage/forge entry points route requests. Existing executable support/publisher suites are reported separately. No test result is inferred from a written scenario.

| Scenario | Source assessment and controlling location |
| --- | --- |
| Prepare release message / draft notes / assemble or update notes | Complete-message trigger routes manage → forge highlights → report assembly; forge SKILL and manage workflows. |
| Collect release highlights only | Shared highlights remains separate; no forced complete-message file; forge SKILL and highlights entry. |
| Explicit supplied-text-only editing | Narrow editorial scope preserved; message entry and report assembly. |

| Same source, changed verified ancillary facts | Refresh applicable sections; no false source-only no-op; message persistence. |

| Optional structure/duplicate sections | Omit empty headings/quotas, preserve template, avoid repeated highlights and redundant title; report complete-message section. |

## Cross-owner reconciliation

README and capability map advertise complete-message preparation with the selected default, while preserving highlights-only scope. Publisher handoff receives the whole final body, not just its highlights. Verification separates retained complete message from consumable internal coverage. No executable publisher API or release creation policy changes are needed: its existing exact-source notes/hash transfer accepts the complete body.

## Limits

Atomic save and owner-routing behavior are defined in skill instructions; this assessment does not establish that an installed agent follows them. No new product release, final message for SDD Manager itself or client acceptance run is performed. Existing source-only tests cannot certify human-curation quality or native failure handling.
